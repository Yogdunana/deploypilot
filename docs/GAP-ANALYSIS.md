## 二、关键差距（按严重程度排序）

### 🔴 严重 — 阻塞用户使用

#### 1. 安装脚本二进制 ~~是占位符~~ ✅ 已解决

**现状：** v1.0.0 已通过 GitHub Release 自动发布预编译二进制（linux/amd64 + linux/arm64），安装脚本已支持从 Release 下载。Docker 一键部署也已可用。

**产物：** 每次 tag push 自动构建 6 个二进制文件（deploypilot/api-server/mcp-server × amd64/arm64）并上传到 GitHub Release。

---

#### 2. ~~缺少~~ GitHub Release 自动发布 ✅ 已解决

**现状：** `release.yml` 工作流已配置，每次推送 `v*` tag 自动构建多平台二进制并创建 GitHub Release。Docker image 同步发布到 `ghcr.io/yogdunana/deploypilot:<version>`。

---

### 🟡 中等 — 影响核心体验

#### 3. 1Panel 集成功能不完整

**现状：** `panel_1panel.go` 只实现了 3 个 API 调用：

| 已实现 | 未实现 |
|--------|--------|
| OpenFirewall（开放端口） | 站点创建/管理 |
| CloseFirewall（关闭端口） | 删除反向代理 |
| CreateReverseProxy（创建反代） | SSL 证书管理 |
| | 数据库管理 |
| | 容器管理 |

**影响：** 用户期望的 "自动同步 1Panel" 体验不完整。比如部署完成后，1Panel 里看不到新站点，只能看到防火墙规则和反代。

**需要做的：**
- [ ] 添加 `DeleteReverseProxy` 方法
- [ ] 添加 `CreateWebsite` 方法（创建站点）
- [ ] 添加 `GetWebsiteList` 方法（查看站点列表）
- [ ] 考虑添加 SSL 证书管理方法

---

#### 4. 宝塔面板集成同样不完整

**现状：** `panel_btpanel.go` 存在，但 `PanelProvider` 声称支持的功能（website_management, database, ftp, ssl, cron）远多于实际实现。

**需要做的：**
- [ ] 审查宝塔面板实际实现了哪些 API 调用
- [ ] 补齐与 1Panel 对等的功能

---

#### 5. 缺少 1Panel API 开启提醒

**现状：** 前端和 MCP 工具中都没有 "请先开启 1Panel API" 的友好提醒。用户配置 1Panel 时如果 API 未开启，只会得到一个模糊的连接失败错误。

**需要做的：**
- [ ] 前端：在添加 1Panel Provider 页面，API Key 输入框下方显示黄色提示条
- [ ] MCP：当 1Panel 连接失败时，返回包含开启步骤的友好错误信息
- [ ] API：当 1Panel API 返回 401/403 时，返回特定错误码和引导文案

---

#### 6. 自动端口分配机制不明确

**现状：** 这是用户初心场景的核心功能（3 个项目都默认 5000 端口），但代码中未确认是否有自动端口分配逻辑。

**需要做的：**
- [ ] 审查 `deploy_app` MCP 工具和 `create_app` API 是否支持自动端口分配
- [ ] 如果不支持，需要实现：检测端口占用 → 自动分配可用端口 → 配置容器端口映射
- [ ] 在 Nginx/反代配置中使用分配的端口

---

### 🟢 轻微 — 影响体验但不阻塞

#### 7. README 缺少核心痛点描述

**现状：** 当前 README 以 "AI-Native Deployment Management Platform" 开头，全是功能列表，没有讲清楚 "AI IDE 沙箱无法 SSH" 这个核心痛点。

**已解决：** 本报告配套的新版 README 已重写。

---

#### 8. Kubernetes MCP 工具有未定义函数

**现状：** 之前修复了 `server.go` 中的 Git 合并冲突标记，但 K8s 相关的 MCP 工具（`handleListClusters`, `handleK8sDeploy` 等）的实现状态需要确认。

**需要做的：**
- [ ] 验证所有 K8s MCP 工具是否正常工作
- [ ] 如果 K8s 不是近期优先级，考虑从 MCP 工具列表中移除未完成的工具

---

#### 9. 缺少 MCP 上下文记忆

**现状：** 每次 MCP 调用都是无状态的，AI 不记得上一次做了什么。

**影响：** 用户说 "把刚才部署的项目回滚"，AI 不知道"刚才"是哪个。

**需要做的：**
- [ ] 实现会话级操作历史
- [ ] 提供 `list_recent_operations` MCP 工具

---

#### 10. ~~缺少~~ OAuth 登录 ✅ 已实现

**现状：** v1.0.0 已实现 GitHub/Gitee OAuth2 登录，支持 CSRF 保护（state 参数）、自动用户创建、角色分配。

**优先级：** ~~P3~~ 已完成。

### 第三优先级：提升质量

7. **更新 README** — 使用新版痛点驱动的 README
8. **K8s 工具审查** — 移除或补齐未完成的 K8s MCP 工具
9. **端到端测试完善** — 覆盖核心部署流程

## 五、结论

DeployPilot 的**架构设计和代码质量已经相当成熟**——MCP Server、REST API、部署引擎、Provider 插件体系、安全体系、Web 面板全部就位。

**最大的差距不在代码，而在「最后一公里」：**
- 安装脚本下载的是假二进制
- 没有可下载的 Release 产物
- 用户无法真正安装和运行

**建议：** 集中精力先打通安装 → 运行 → 首次部署这条链路，再完善 1Panel 集成和自动端口分配等体验功能。代码基础已经足够好，只需要把最后一块拼图补上。
