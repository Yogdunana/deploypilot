## 一、项目初心与定位

### 1.1 核心问题

**AI IDE（TRAE Solo、SOLO、Claude、Cursor、扣子/Coze、豆包）全部运行在云端沙箱中，无法 SSH 到用户的服务器。**

同时，企业级服务器通常处于内网环境，必须通过指定跳板机才能访问，Cursor 和 TRAE IDE 都无法直接连接。

这意味着 AI 帮不了用户完成部署上线——改端口、配反代、解析 DNS、申请 SSL、放行防火墙，全得手动做。

### 1.2 产品定位

**DeployPilot = AI 与服务器之间的安全桥梁**

- 部署在用户自己的服务器上（self-hosted）
- 通过 MCP 协议暴露工具，让沙箱中的 AI IDE 能远程、安全地操控服务器
- 对标 1Panel / 宝塔的安装体验：一行脚本，全自动
- 支持跳板机/Bastion 场景：企业内网服务器也可通过 DeployPilot 桥接部署
- **不是 SaaS、不是给多人用的平台、不是另一个面板**

### 1.3 核心价值主张

> **像 1Panel 一样简单安装，像 AI 助手一样全自动部署。一次安装，永久解放双手。**

### 1.4 市场差异化

| 产品 | 面板 | AI 对接 | MCP | 全链路自动化 |
|------|:----:|:-------:|:---:|:-----------:|
| 1Panel / 宝塔 | ✅ | ❌ | ❌ | ❌ |
| AI SSH 客户端 | ❌ | ✅ | ❌ | ❌ |
| Dokploy / Coolify | ✅ | ❌ | ❌ | 部分 |
| **DeployPilot** | **✅** | **✅** | **✅** | **✅** |

**DeployPilot 是目前唯一将「面板 + AI + MCP + 全链路自动化」闭环的产品。**

## 二、目标用户

### 2.1 核心用户画像

1. **AI 编程重度用户** — 天天用 SOLO / Claude / Cursor / 扣子写项目，写完想一键上线
2. **自建服务器用户** — 有自己的服务器，用 1Panel / 宝塔管理
3. **懒人全自动化玩家** — 不想手动配 Nginx、DNS、SSL、防火墙
4. **多项目开发者** — 同时跑多个项目，端口冲突是日常痛点
5. **企业内网运维** — 服务器在跳板机后面，需要通过 DeployPilot 桥接才能让 AI IDE 部署

### 2.2 用户使用流程

```
1. 用户 SSH 到服务器（仅第一次）
2. 执行一行安装脚本
3. 脚本自动生成账号密码、启动服务
4. 用户打开网页，登录后台
5. 填入 1Panel API Key / DNS 凭据（有引导提示）
6. 在 AI IDE 配置 MCP 连接
7. 之后：AI 写代码 → AI 一键部署 → 全自动上线
```

### 3.2 核心设计原则

1. **MCP 优先** — AI IDE 的唯一调用入口是 MCP，不是 SSH、不是 CLI
2. **安装极简** — 对标 1Panel/宝塔，一行脚本，全自动
3. **安全第一** — JWT + ws-ticket + AES-256-GCM + RBAC + 审计日志
4. **凭据托管** — 所有第三方密钥由 DeployPilot 统一加密存储和管理
5. **Provider 可插拔** — DNS/通知/面板/CI-CD 全部插件化

### 3.3 安全架构

```
用户登录 → JWT（登录态）
    │
    ├── REST API 请求 → 携带 JWT → RBAC 权限校验
    │
    ├── WebSocket 连接 → JWT 换取 ws-ticket（一次性票据）
    │                     └── 防止 JWT 暴露在 URL 中
    │
    └── MCP 工具调用 → JWT 认证 + 角色权限检查
                        └── 凭据解密（AES-256-GCM）
```

## 五、安装体验设计（对标 1Panel/宝塔）

### 5.1 安装流程

```
用户执行: curl -fsSL https://raw.githubusercontent.com/.../install.sh | bash

脚本自动完成:
  1. 检测操作系统（Ubuntu/Debian/CentOS）
  2. 检测并安装依赖（Docker 等）
  3. 下载 DeployPilot 二进制
  4. 创建配置文件
  5. 自动生成:
     - 管理员用户名（admin）
     - 随机强密码（16位，含大小写+数字+特殊字符）
     - JWT 密钥（32字节随机）
  6. 注册 systemd 服务 + 开机自启
  7. 启动服务
  8. 输出访问信息

终端输出:
  ╔══════════════════════════════════════════════╗
  ║        DeployPilot 安装成功！                  ║
  ╠══════════════════════════════════════════════╣
  ║  访问地址: http://1.2.3.4:8080               ║
  ║  用户名:   admin                              ║
  ║  密码:     xK9m#pL2$vQ7nW4                   ║
  ║                                                ║
  ║  ⚠️  请立即登录并修改默认密码！                ║
  ╚══════════════════════════════════════════════╝
```

### 5.2 首次配置引导

用户登录后，DeployPilot 应引导完成：

1. **修改默认密码** — 强制要求
2. **添加服务器** — 填入服务器信息
3. **配置 1Panel（可选）** — 引导开启 API 并填入 Key
4. **配置 DNS（可选）** — 选择 DNS 服务商并填入凭据
5. **配置通知（可选）** — 设置告警通知渠道

### 5.3 1Panel API 开启提醒

**触发时机：**
- 用户在网页端添加 1Panel Provider 时 → 输入框下方黄色提示
- AI 通过 MCP 调用 1Panel 相关工具但连接失败时 → MCP 返回友好错误信息

**提示文案：**
```
⚠️ 1Panel API 默认关闭，需要手动开启：

1. 登录 1Panel → 右上角「设置」
2. 进入「面板设置」→ 打开「API 接口」开关
3. 复制生成的 API Key 粘贴到此处

开启后，DeployPilot 可自动管理防火墙、端口、反向代理。
```

```
用户: "帮我把这个项目部署到服务器上"

  1. detect_environment → 检查服务器环境
  2. create_app → 创建应用（自动分配端口）
  3. deploy_app → 执行部署

  5. [SSL 自动申请]

  访问地址: https://myapp.example.com
  端口: 5001（自动分配）
  SSL: 已自动申请
  1Panel: 防火墙已放行"
```

## 八、风险与约束

| 风险 | 影响 | 缓解措施 |
|------|------|---------|
| 1Panel API 必须手动开 | 用户可能卡住 | 多处友好提醒 + 详细引导 |
| AI IDE MCP 支持不一 | 部分 IDE 无法使用 | 同时提供 REST API 作为备选 |
| 安装脚本兼容性 | 不同 Linux 发行版 | 脚本内置多系统检测 |
| 凭据安全 | 密钥泄露风险 | AES-256-GCM 加密 + 审计日志 |
| 单点故障 | DeployPilot 挂了全挂 | systemd 自动重启 + 自愈引擎 |
